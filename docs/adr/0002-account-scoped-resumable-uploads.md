# ADR-0002：账号隔离、连接超时与可恢复上传

日期：2026-09-09。状态：本地实现完成，待部署及真机验收。

## 背景

退出账号后仍可能存在旧 BLE 连接、延迟网络结果；部分 GATT 服务发现和网络响应正文没有完整超时。上传完成回复丢失时，重新创建批次可能导致同一份本地数据重复入库。

## 决定

1. 退出/替换账号使旧任务失效，取消认证请求和蓝牙等待，关闭账号的 GATT 与 Notify。已经完整保存的文件仍保留在原账号下。Token 写入和清除按调用顺序执行，防止晚到写入复活已退出凭证。
2. 每项蓝牙连接准备操作有应用层超时；超时连接迟到后不允许注册为当前连接，也不能取消另一轮较新的连接。原有五次自动重连上限保持不变。
3. API 普通请求的 15 秒、上传的 60 秒覆盖接收完整正文。刷新凭证另有 15 秒上限；GET 仍最多自动重试一次，写入不做无身份的盲重试。
4. 使用现有 expo-sqlite 的键值存储保存上传日志，先持久化请求身份再发请求，保存批次号和固定文件清单。不同合法记录即使内容相同也不按哈希合并。
5. Backend 使用独立追加表 `app_upload_requests`，以账号、操作、请求键联合唯一约束保护重试。请求指纹与结果在同一事务提交；重复请求返回原对象，不新增文件/任务；相同键不同内容返回 409。
6. App 先确认服务支持 `idempotent_uploads: 1`。不支持时保留本地数据并提示更新 Backend，不降级为可能重复写入的上传。
7. 完成批次后逐一核对文件身份、大小、SHA-256、总数和总大小，才能清理本地文件。清理中断保留日志，下次继续查询同一已完成批次。
8. 使用 expo-network 的网络变化通知触发前台续传；失败退避 5、15、30、60 秒，之后间隔不再缩短。成功后每 60 秒检查一次本地队列，以覆盖新增或遗留任务。后台停止调度新任务，回前台恢复；网络通知合并，不并发重复运行。

## 影响与边界

- Backend 必须先发布并创建新表，再安装包含 expo-network 的完整 App 包；不能只给旧原生包热更新 JS。
- 不改固件、Agent、记录页、未读统计，也不改变五次 BLE 重连策略。云端续传退避与 BLE 重连次数是两套独立机制。
- 幂等覆盖同一份已落盘文件的云端重试。固件把同一采样重新作为新记录发送的跨会话去重，需要固件提供稳定采样记录 ID；不能仅用 blockId/内容哈希假定是重复。
- 本次不承诺锁屏/后台持续传输，也不把模拟蓝牙测试当作真机并发/距离测试。
- 新后端对旧 App 保留原有上传接口；回滚 App 可保留新表。新 App 不应搭配回滚到不支持幂等的后端运行。
